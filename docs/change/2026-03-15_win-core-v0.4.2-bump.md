# Win：升级 Core 到 v0.4.2 并准备 v0.0.4

## 变更背景 / 目标
- B 电脑当前使用的 release 包仍依赖 `myflowhub-core v0.4.1`；
- Windows RFCOMM dial 最新修复已在 Core 中完成，但未进入 Win release；
- 本次目标是将 Win 依赖升级到 `v0.4.2`，并准备发布 `v0.0.4`。

## 具体变更内容
### 修改
- `go.mod`
  - 将 `github.com/yttydcs/myflowhub-core` 从 `v0.4.1` 升级到 `v0.4.2`。
- `go.sum`
  - 同步新的模块校验信息。

### 新增
- `plan.md`
  - 记录本轮依赖升级与发布准备任务。
- `docs/change/2026-03-15_win-core-v0.4.2-bump.md`
  - 归档本次依赖升级、验证与发布说明。

## 对应 plan.md 任务映射
- `WIN-REL-1`：对齐依赖基线
- `WIN-REL-2`：验证桌面端构建与测试
- `WIN-REL-3`：维护发布归档
- `WIN-REL-4`：准备 `v0.0.4` 发布

## 关键设计决策与权衡
- **只升级 Core，不顺带调整业务层**
  - 本次目标是把最新 Windows RFCOMM 修复带入 release，不引入新的 UI/逻辑风险。
- **保留现有 release workflow**
  - 继续由 `.github/workflows/release.yml` 在 tag 推送后自动构建发布，减少人工发布分叉。
- **以发布版本作为依赖**
  - 不使用临时 replace 或 commit hash，保持依赖解析与下游用户环境一致。

## 测试与验证方式 / 结果
- 依赖解析：
  - `GOWORK=off go list -m -f "{{.Path}} {{.Version}}" github.com/yttydcs/myflowhub-core`
  - 结果：`github.com/yttydcs/myflowhub-core v0.4.2`
- 仓库验证：
  - `GOWORK=off go test ./... -count=1`：通过
- 发布准备：
  - 确认 `v0.0.4` tag 需落在 `origin/main` 上，以满足 GitHub Actions 规则；
  - 当前依赖升级和文档已在独立 worktree 完成，待 workflow 收口后即可合并并推送 release tag。

## 潜在影响与回滚方案
- 潜在影响：
  - Win release 的最低 Core 基线提升到 `v0.4.2`；
  - B 电脑需要下载新的 release 包才能拿到最新修复。
- 回滚方案：
  - 回退依赖升级提交；
  - 删除错误的 `v0.0.4` tag，并重新发布修正版本。
