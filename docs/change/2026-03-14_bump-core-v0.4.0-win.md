# Win：对齐 Core v0.4.0 / SDK v0.1.4

## 变更背景 / 目标
- `MyFlowHub-Core v0.4.0` 与 `MyFlowHub-SDK v0.1.4` 已发布，需要将桌面端仓库的依赖基线同步到最新版本。
- 本次仅做版本对齐，不调整桌面端业务逻辑、界面行为和协议语义。

目标：
- 将 `github.com/yttydcs/myflowhub-core` 升级到 `v0.4.0`。
- 将 `github.com/yttydcs/myflowhub-sdk` 升级到 `v0.1.4`。
- 保证仓库在 `GOWORK=off` 下可通过测试。

## 具体变更内容
- 依赖升级：
  - `go.mod`
  - `go.sum`
- 版本变更：
  - `myflowhub-core: v0.2.0 -> v0.4.0`
  - `myflowhub-sdk: v0.1.2 -> v0.1.4`
- 工具链联动调整：
  - `go 1.23.0 -> 1.25.0`
  - 移除 `toolchain go1.24.5`
  - `github.com/godbus/dbus/v5` 升级到 `v5.2.2`
  - `golang.org/x/sys` 升级到 `v0.42.0`

## 对应计划任务映射
- `REM-3`：Win 对齐 Core v0.4.0 / SDK v0.1.4

## 关键设计决策与权衡
- 接受 Go 最低版本提升：这是 `Core v0.4.0` 的直接约束，保留旧 `toolchain` 只会引入后续构建分叉。
- 不额外修改业务层代码：本次验证表明依赖升级后现有调用仍兼容，因此不扩大变更面。
- 继续沿用 Wails 的 `frontend/dist` 验证约束：测试前临时创建占位文件满足 `go:embed`，避免把前端构建产物错误纳入版本库。

## 测试与验证方式 / 结果
在 `go1.25.0`、`GOWORK=off` 下执行：
- 临时创建 `frontend/dist/.keep`
- `go test ./... -count=1` ✅

说明：
- `frontend/dist/.keep` 仅用于本地测试满足 `go:embed` 前置条件，目录由 `.gitignore` 忽略，未纳入提交。

## 潜在影响
- 桌面端最低 Core 依赖提升到 `v0.4.0`，最低 Go 版本提升到 `1.25.0`。
- 本地或 CI 在直接执行 `go test` / `go build` 前，仍需保证 `frontend/dist` 至少存在一个文件，或通过既有前端构建流程生成该目录。

## 回滚方案
- 回退本次提交，并重新执行 `GOWORK=off go mod tidy` 恢复旧依赖图。
- 若后续仅出现局部兼容问题，优先通过增量修复解决，不直接回退整体版本对齐。
