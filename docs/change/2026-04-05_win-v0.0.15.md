## 经验 / 教训摘要
- 应用层仓库如果把 repo-local `replace` 留在正式发布状态，`GOWORK=off` 验证和外部 clone 都会失真。
- Win 这类 Wails 仓库的 release-state 验证不能只看 Go 侧，还必须确认 `wails generate module` 和前端依赖状态。

## 可复用排查线索
- 症状
  - `go.mod` 仍出现 `../../worktrees/proto-server-release-align`
  - `GOWORK=off` 下解析不到当前 Proto 类型
  - `wails generate module` 或 targeted Go tests 依赖本地 sibling repo
- 触发条件
  - Win 主线已经消费更高 Proto baseline，但 release-state 没有把 `replace` 收口
- 关键词
  - `proto-server-release-align`
  - `myflowhub-proto v0.1.7`
  - `wails generate module`
  - `GOWORK=off`
- 快速检查
  - 检查 `go.mod` 是否仍保留 proto `replace`
  - `GOWORK=off wails generate module`
  - `GOWORK=off go test ./internal/services/flow ./internal/mcp ./internal/mcpapp -count=1 -p 1`
